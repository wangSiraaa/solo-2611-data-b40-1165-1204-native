# 冬季苗床认养样例

坐标起自 0，地形是一条 1×4 的格带：列 0 是北墙，列 1、2 分别是东畦 `E`、西畦 `W`，列 3 为备用格。
初版北墙高 1；`raised_wall` 只把北墙改成高 2，苗床格不动。每张方向卡给出射线经过的沿线格与该拍射线高度，
中途格“标高达到射线”（`elevation >= ray_height`）即遮住该拍，遮挡格逐块记下来源块与修订号。

## 开口（clear）与遮挡（blocked）

- 东畦上午（第 1、2 拍）射线高 2：北墙高 1 时不达到，放行；北墙升到 2 时正好达到，两拍全挡。
- 东畦下午（第 3、4 拍）射线高 1：墙高 1 即达到，下午本就无日照。
- 西畦上午射线高 1（被挡），下午射线高 3（高于两版墙，放行）。

故初版地形上：东畦上午连晴、西畦下午连晴。整日天气表给出 `CLEAR`（四拍全晴）与
`CLOUD_AM`（首拍多云、其余晴）两种可能，同一种天气对所有畦同时生效，不能跨畦挑天。

## 两张认养单

- `FIX-EAST`（固定种植畦）：一盘苗钉在东畦，要连续两拍日照，天气仅 `SUN` 全晴。
  - 在初版（墙高 1）签约：东畦上午两拍放行，如约可签。
  - 仅发布北墙高 2 的新版本后同条件再签：上午两拍都被挡，**拒绝**，证据逐拍给出遮挡格与来源块
    （`NORTH@2`），不写合同行。
  - 恢复原地形、但把东畦第 2 拍床位划给已签客户（`occupied`）且园内无替畦：固定苗不能移床，
    交接判 `failed`，记录 `bed_occupied`。
- `MOB-EW`（带轮苗床）：一盘苗起于东畦，持有东、西两畦使用权，要连续两拍日照。
  - `CLEAR`：留在东畦，上午第 1、2 拍即凑足连照，无需移动。
  - `CLOUD_AM`：首拍多云；第 2 拍沿 `E-W` 通道推到西畦，**移动这一拍不记日照**；
    西畦下午第 3、4 拍连晴，凑足两拍。移动需要空通道与当班园丁。
  - 天气在首拍早晨才揭晓（`reveal=dawn`），策略树在第 1 拍即按天气类型分支；
    选 `progressive` 时第 1 拍动作必须被所有尚未区分的天气共用。
  - 签约时园丁为 0 且移动不可或缺 → 直接拒绝；交接当天当班园丁为 0、或西畦目标床位被占，
    交接判 `failed` 并分别留 `no_gardener` / `bed_occupied` 证据。

## 命令行

```bash
# 签约（两份请求分别试；改 source_revision=2 可复现北墙升高后的拒绝）
python3 -m slabwater adopt <db_dir> materials/winter-garden/sign_fixed.json
python3 -m slabwater handover <db_dir> handover.json
python3 -m slabwater contract <db_dir> <contract_id>   # 重开，取回畦权与逐拍日照记录
```

合同冻结签约时的地形版本与 `elevation_hash`；之后北墙再出新版不改写旧合同，交接可另给
`observed_revision` 在新地形上实地核验，报告同时保留“签约地形”和“实测地形”两份哈希。
